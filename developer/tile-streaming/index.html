    Scenery streaming: how it works and how to maintain it

    User-facing behaviour is described in AutoOrtho scenery. This page covers the design and the maintainer tasks: building tile indexes, repackaging scenery for streaming, and adding a scenery set.

    The streaming package is AutoOrtho's only scenery package now: tiles are downloaded on the map (kept, never evicted) or as X-Plane opens them, and regions installed with the old region installer can be moved into it. The region installer (downloader.py) is no longer offered in the UI; its code stays for the command line and for installed regions' Scenery Options.

    Design

    Scenery releases are zip files on GitHub Releases. Every member of a zip is compressed on its own and the zip's central directory records where each one starts, so a single DSF or water mask can be read with an HTTP Range request without downloading the rest. GitHub release assets support Range requests and have no bandwidth limit, so streaming needs no paid hosting.

    Streaming packages

    A streaming package is a folder in z_autoortho/scenery/ holding ao_stream.json (the marker) and tile_index.json.gz. It is mounted like an installed region:

    • z_ao_stream_<set>: base mesh (kind: ortho).
    • yAO_stream_<set>_overlays: overlays (kind: overlay), optional.

    The marker records the set, the index URL and its Last-Modified, the disk limit (overlays get a quarter of the ortho limit) and, on the ortho package, the terrain reflectivity (roughness), which synthesize_ter appends to every generated .ter as SUPER_ROUGHNESS (set_stream_roughness), and seasons (set_stream_seasons, XP11 set). fetch_missing: false on every package (set_fetch_missing) offers X-Plane only stored tiles: dsf_names lists none from the index (the mount lists the folder's own files), streams/remote_size refuse unstored DSFs, and prefetch_neighbors does nothing, so X-Plane uses Global Scenery elsewhere. Masks are still offered, since a stored tile must never miss one. _create_package keeps fetch_missing and seasons when it rewrites a marker, and change_stream_source carries fetch_missing to the new set.

    Installed packages built with X-Plane 12's seasonal rasters (spr*, sum*, fal*, win* in the DSF's DEMN table, as in the XP12 set) show Seasons as Included (SeasonsApplyStatus.INCLUDED), and the Seasons patch isn't offered. package_has_native_seasons checks the package's first DSF and caches the answer in .ao_native_seasons.json next to it, because unpacking a 7z DSF takes seconds. Code only ever deletes folders that contain a marker.

    What happens on open

    1. readdir lists the DSFs stored in the package folder plus every DSF in the index (unless fetch_missing is off); installed regions' DSFs are hidden, so installed tiles always win. A stored DSF the index doesn't have (a moved region's newer tile) is listed and opened like any file.
    2. When X-Plane opens a DSF that isn't stored yet, it is fetched (zip local header + member) and stored; 7z-compressed DSFs are unpacked. The DSF's terrain list registers its imagery tiles with TerrainTileLookup and queues its water masks. The 8 neighbouring tiles are prefetched, and their masks are queued as soon as each one arrives.

    Downloads run in three queues so what X-Plane needs soonest goes first: opens in the foreground pool; water masks in their own pool (PriorityWorkers, never capped), masks of tiles X-Plane opened ahead of masks of prefetched tiles; neighbour DSFs in the background pool, at most MAX_BACKGROUND (32) queued. X-Plane reads a tile's masks seconds after its DSF, so masks must never wait behind, or be dropped for, 15 MB DSFs. 3. .ter files are generated from their names with the Ortho4XP template (synthesize_ter). Index builds check every published .ter against it; the few that differ are stored in the index as exceptions. 4. If a fetch fails, an ortho DSF is served from X-Plane's Global Scenery, an overlay DSF as a valid empty overlay, and a water mask as a blank (all-sea) PNG of the mask's size. X-Plane must never see a missing file: a .ter whose mask is missing stops it with a fatal error. 5. An open (X-Plane waiting) always gets its own download and retries it until open_timeout (30 s) runs out. It never waits behind a prefetch of the same file, which may be stuck on a dropped connection; whichever download finishes first stores the file. An open that failed is remembered for 5 minutes so an offline sim falls back immediately.

    GitHub access

    releases/download/... redirects to a signed URL valid for about an hour. RemoteAssets reuses the signed URL until shortly before it expires, so normal flying makes about one request to github.com per zip per hour; the rest go to the asset CDN. On 403, 429 or 5xx, fetches pause (honouring Retry-After, 60 s doubling up to 15 min) and opens fall back meanwhile.

    The CDN and home routers drop idle connections without telling either end; reusing one stalls until Windows reports the reset, about 20 s later. So pooled connections idle for more than 30 s are closed before the next request (RemoteAssets.IDLE_RESET; a new TLS connection costs about 0.1 s), requests use a 5 s connect and 10 s read timeout (the read timeout is the longest silence between bytes, not the whole download), and a dropped or stalled connection is retried up to 3 times.

    Disk limit

    After fetches, and at most once a minute, the least recently used tiles are removed until the package is under 90% of its limit. Files used in the last two hours are kept. Use is tracked by file mtime (touched on open).

    Pinned tiles (downloaded on the map) are listed in pinned_tiles.json in each package ({"tiles": ["+47-123", ...]}; read_pins/write_pins). evict skips their DSFs and masks and leaves them out of the total, so pinned tiles don't count toward the limit. A mask belongs to the tile that holds its centre (mask_cell). The pins live in their own file rather than the marker because _create_package rewrites the marker.

    Scenery & Cache view

    The map on Flight Plan & Map has a Scenery & Cache view (CachePanel) that shows, deletes, downloads and pins what is stored per 1x1 degree tile. The Select a region… picker selects every tile of an area of the set: stream_regions groups the index's DSFs by the region of the zip each is in (TileIndex.regions, labels in tile_stream.REGION_LABELS); it is read on the scan thread. The file work is in cache_inventory.py, which has no Qt dependency:

    • scan(ao_scenery_dir, cache_dir) builds a CacheInventory of CellUsage per tile with os.scandir only. On Windows the directory entries carry size and mtime, so about 200k chunk files take about 1.2 s. The UI runs it on a thread and drops results from older scans.
    • Streamed mesh: DSFs (dsf_cell) and masks (mask_cell) of every package with a marker, plus the pins.
    • Chunk JPEGs in cache_dir: the name is <col>_<row>_<zoom>_<maptype>.jpg (column first, see Chunk.chunk_id in getortho.py). A chunk belongs to the tile holding its centre. Row and column halves are memoised.
    • Built textures: dds_cache/<10 degree band>/<1 degree tile>/<maptype>/; the tile folder name is the tile, and the zoom comes from _z<zl>.dds.
    • The long-term cache (long_term_cache_dir) isn't scanned.
    • delete_cells(..., mesh, imagery) removes only files AutoOrtho names itself: DSFs and masks inside marked packages, chunk files matching the chunk naming, and the tiles' dds_cache folders (empty band folders go too). Deleting a tile's mesh also unpins it. A mask on a degree line may also be used by the neighbouring DSF; that DSF fetches it again on its next open (note_local_dsf).
    • keep_offline(...) creates a StreamPackage per package (with the same hidden set the mount uses, so installed tiles aren't fetched), pins the tiles its index has, and calls StreamPackage.download_tile for each, KEEP_WORKERS (4) tiles at a time: fetch_now (synchronous fetch) of the DSF, then fetch_many of the masks its terrain list names (tile_masks / mask_rels). fetch_many groups members that sit close together in one zip (coalesce_runs: gaps under 256 KB, reads up to 64 MB) and reads each group with one Range request (fetch_run). A tile's masks are mostly one run (XP12 set: 48 masks per tile, one run for 90% of tiles), so a coastal tile takes 6 to 16 requests instead of 170 to 430. Measured on the XP12 set: 0.96 s per tile with 4 workers against 2.7 s one at a time. A throttled host stops new tiles from starting; what was fetched stays pinned. Progress goes to the Activity panel as a TaskType.CACHE task, cancellable between tiles and between reads.
    • mesh_download_estimate sums the index sizes of DSFs not on disk yet, and estimate_imagery counts web-mercator tiles per tile and zoom (chunks_in_cell) times the average chunk size already in the cache (16 KB if there's none). Both feed the Download dialog.
    • With seasons on an XP11 package, keep_offline patches each tile after downloading it (stream_seasons.patch_tile); a failure leaves the tile as downloaded.

    Deleting and keeping are locked while AutoOrtho or X-Plane runs: MainWindow._set_runtime_locked passes the same flag to the stream panel and to CustomMapEditor.set_runtime_locked. After a change the panel rescans and emits cacheChanged, which refreshes the stream panel's usage.

    Imagery downloaded ahead

    The Download dialog's Imagery choice (CachePanel._ask_download) downloads the tiles' imagery after their mesh (download_imagery in cache_map_panel.py, file work in kept_imagery.py):

    1. plan reads each stored DSF's terrain list (terrain_tiles: row, col, maptype, zoom per texture; each texture is 16x16 chunks at its zoom) and covers every texture at the chosen zoom (texture_chunks). The provider is resolved as getortho's TileCacher._resolve_maptype does (maptype_resolver: override, custom map per tile, or the scenery's). Chunks already in cache_dir are skipped; Apple Maps is skipped (it needs the pipeline's session token). A 1x1 degree tile at 45°N is 56,576 chunks (about 0.9 GB) at ZL16 with Bing; planning takes about 1 s.
    2. download fetches with provider_urls.tile_url, 8 workers, writes <col>_<row>_<zoom>_<maptype>.jpg atomically, treats Bing's X-VE-Tile-Info: no-tile and 404 as no imagery, retries dropped connections, and stops on 403/429. About 58 chunks/s measured with Bing.
    3. Only a complete run records the tiles in kept_imagery.json in cache_dir (tile -> highest zoom kept, set_kept).

    The mount workers read that file at start (downloading is locked while AutoOrtho runs) and skip kept tiles in all three cleanups: the JPEG disk budget and the JPEG cleanup after a texture is built (protector, combined with the low-zoom base's predicate in protect_jpeg; the budget doesn't count those files either), and the DDS cache's LRU eviction (dynamic_dds_cache.protect_dds, from dds_protector, which reads the tile folder under dds_cache/<band>/). Deleting a tile's imagery and Stop Keeping drop it from the record.

    Moving installed regions in

    region_adopt.adopt_regions moves regions the old installer put in z_autoortho/scenery/z_ao_<id> (with z_autoortho/<id>_info.json) into the ortho streaming package. All of them come from the XP11 set, so it requires an XP11 package (their .ter files need mask zoom 14) and that the index knows at least half of a region's DSFs. Files move as they are, not checked by CRC: on real installs the Seasons patch had 7z-compressed and rewritten DSFs, regions overlap (the index takes a shared tile from one region's zip), and newer releases have tiles the index lacks; all of these load. Tiles are pinned first, DSFs move before masks (a DSF still in the region keeps its masks), and the folder and info file go last, so an interrupted move finishes on the next run. A patched reflectivity carries over to the marker. Overlay DSFs in Custom Scenery/yAutoOrtho_Overlays that the overlay index has move into the overlay package. check_regions is the cheap check (lists and stats files, about 10 s cold for five regions) behind the Installed regions section.

    region_adopt.migrate runs this for every installed region when the app starts (MainWindow._migrate_installed_regions), or once AutoOrtho and X-Plane have stopped if they were running; on_run waits while it runs. Without an ortho package it first sets up the XP11 set with fetch_missing off (and no overlay package), which behaves like installed regions did, and turns seasons on if a moved region had the Seasons patch; if that index download fails nothing changes and the next start tries again. yAutoOrtho_Overlays is never moved: it works with any set, and moving it into an XP11 overlay package would lose it on a switch to XP12. A region stays installed when scenery_packs.ini has it as SCENERY_PACK_DISABLED (disabled_packs), or when it is on another drive (st_dev differs) and the package drive lacks its size plus 2 GB; with room, _move copies to a .part name and swaps it in, and a junction or symlink region is unlinked rather than emptied with rmtree. Into a package of another set, a region brings its own terrain/*.ter (a real file in the package wins in ter_bytes) and every texture in its textures/ (XP11 water edges use water_transition.png, which the XP12 index doesn't have). Masks and terrain are hard-linked before DSFs move, so an interrupted move never leaves a DSF without its files.

    change_stream_source carries kept tiles into the new set (carry_kept_tiles): it reads each kept DSF's terrain list, downloads any texture the old folder never stored (failing before anything moves), writes the terrain files with the old set's settings as real files, links the textures, then moves the DSFs and the seasons record. With replace_kept (the switch dialog's Replace), tiles the new index has are only pinned in the new package and MainWindow._download_kept downloads them from it through the Scenery & Cache panel; tiles it lacks are carried as above.

    Moved files the new index doesn't have can't be downloaded again, so evict skips them and the map's Delete leaves masks the index lacks.

    Tiles of another set

    tile_sources.json in a package lists the tiles from another set ({"tiles": {"+47-123": "xp11"}}, read_tile_sources); every other stored tile is the package's own set. _adopt_checked (with its own terrain) and carry_kept_tiles write it. Packages migrated before it existed are filled in once by backfill_tile_sources from the inventory scan: a package stores its own downloads exactly as the index sizes them (34 of 34 on a real XP12 install), so a kept DSF of another size is from the other set; it only runs where real terrain files exist.

    forget_foreign_tiles deletes such tiles' DSFs with the real terrain files and unindexed masks only they used: a file goes when its texture area (texture_cells) touches a tile being removed and no other tile of another set. Leaving one would make a tile of the package's own set downloaded there later use the old set's terrain. The map's Delete calls it, and so does Use XP12 for N tiles… (switch_to_current_set, then Download). The Scenery & Cache view shows the set per tile (CellUsage.mesh_set, Colour by: Scenery set, hover text).

    Seasons for downloaded XP11 tiles

    stream_seasons.patch_tile runs DsfUtils.add_seasons_to_dsf_file on a stored DSF (no backup: it can be downloaded again) and records the DSF's size and mtime in seasons_tiles.json; pending_tiles lists pinned stored tiles that don't match, so a tile downloaded again counts as unpatched. A real 33 MB XP11 tile takes about 34 s.

    DsfUtils.season_raster_lines picks Global Scenery rasters by name. X-Plane 12.1+ lists sea_level between elevation and the seasons; the old loop stopped there, so patched DSFs got a lone RASTER_DEF elevation with no data and no seasons. A DSF with raster lines but no season rasters is now repaired instead of skipped.

    Building and publishing indexes

    Indexes live in the tile-index pre-release of this repository (tile_stream.INDEX_BASE_URL). Installed packages check them for updates once a week with If-Modified-Since.

    XP11 legacy set, from kubilus1/autoortho-scenery (reads only zip directories remotely, plus the terrain/ block of each zip for the .ter check):

    python scripts/build_tile_index.py --out dist/tile-index/tile_index_xp11.json.gz
python scripts/build_tile_index.py --kind overlay --out dist/tile-index/overlay_index_xp11.json.gz
gh release upload tile-index dist/tile-index/*.json.gz --clobber

    A set hosted as one release per area, from local copies of the release files (repeat --local-dir per area; {area} is filled from each folder's <area>_info.json). The XP12 set is hosted at ProgrammingDinosaur/autoortho-scenery-xp12, one release per area tagged <area>_v1.4: afr-n, afr-s, asi-c, asi-n, asi-s, aus-pac, eur-e, eur-w, greenland, na-n, na-s and sa (18,695 tiles, 238 GB). Each build replaces the index, so pass every area:

    python scripts/build_tile_index.py \
    --local-dir D:/xp12/afr-n/release --local-dir D:/xp12/afr-s/release ... \
    --url-base "https://github.com/ProgrammingDinosaur/autoortho-scenery-xp12/releases/download/{area}_v1.4/" \
    --variant xp12 --name "XP12 set (flightwusel v1.4)" \
    --out dist/tile-index/tile_index_xp12.json.gz

    Index entries are [asset, header_offset, compressed_size, size, method, crc]; the format version is tile_stream.INDEX_FORMAT. Bump it only for incompatible changes, since installed copies refuse unknown formats.

    • Format 2 (written by the builder) packs the entries, because parsing a million JSON lists costs about 500 MB that Python keeps afterwards. files holds names (DSFs and anything else, sorted), masks (base64 of the water masks' sorted little-endian uint64 keys, row << 36 | col << 8 | zoom) and entries (base64 of 24-byte records, <HQIIHI, names first, then masks). See tile_stream.pack_files. The full XP12 index (1.35 million files) loads in about 0.2 s and uses about 50 MB.
    • Format 1 stores files as {path: entry}. It's still read, and AutoOrtho 3.3.0 reads only format 1. So the XP11 indexes stay format 1 under their current names. Publish a format 2 index only for a source that 3.3.0 shows as Soon, or under a new file name.
    • --convert INDEX --out NEW rewrites an index in the current format without reading the releases.

    Repackaging a solid archive

    Packages shipped as one solid .7z (like the XP12 flightwusel set) can't be streamed. scripts/repack_scenery.py turns an extracted package into kubilus-style release zips: whole 1x1 degree tiles per zip, each under 1900 MB, DSFs 7z-compressed inside (X-Plane reads them natively), and an <area>_info.json. The result also works with the classic region installer. Release notes credit the original package and name the zip that holds its README.txt and _docs/ (asi-n ships no README.txt).

    7z x z_ao_greenland_zl16_o4xp1.40.13+je_v1.4.7z -oD:/xp12/greenland/extracted
python scripts/repack_scenery.py D:/xp12/greenland/extracted --area greenland \
    --name "Greenland XP12 (flightwusel v1.4)" --out D:/xp12/greenland/release
gh release create greenland_v1.4 D:/xp12/greenland/release/* \
    --repo ProgrammingDinosaur/autoortho-scenery-xp12

    Then rebuild the set's index (above) with every area uploaded so far.

    Adding a scenery set

    Add an entry to tile_stream.SOURCES with its label, ortho_index and overlay_index (or None) URLs. The first available entry is the default in the panel and the setup wizard (currently xp12). Set available: False to show it as Soon until its index is published. The panel turns Include overlays off for a set without overlays.
